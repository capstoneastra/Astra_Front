# 회원별 업무 공간·상호 대여·DEMO 결제

2026-11-24 · `feat/yeonji`. 최신 사용자 요청으로 기존 ‘회원별 화면은 문서만’ 범위를 확장하여 실제 UI/로직을 구현했다. 백엔드·DB·실제 JWT 서비스는 변경하지 않았다. 명세 기준은 `docs/api-spec.md` §0-4·2·3·5·7·10이다.

## 로그인과 실행

### 2026-11-24 추가: 계정 설정·관리자 운영 시각화

- 모든 회원의 사이드바와 헤더 설정 아이콘에서 `/#/settings`로 이동한다. 이름·연락처 편집, 오류 검증, 저장/변경 취소, 계정 이메일·역할·소속·활성 상태·소속 승인 확인, 테마·장비 검색 기본 보기, 한국 시간대, 업무 알림 이동, 로그아웃을 제공한다.
- `docs/api-spec.md` §1의 **PATCH `/users/me`**에 `name`, `phone` 두 필드만 보낸다. `profileService`는 기존 공통 axios와 응답 envelope를 사용하고 수정 응답의 사용자 ID·역할·소속이 달라지면 거부한다. 저장 후 기존 `checkSession()`으로 계정 정보를 다시 확인한다. 실제 AuthProvider·JWT 갱신·회원가입 코드는 변경하지 않았다.
- 이메일·소속·역할 변경은 직접 제공하지 않는다. 비밀번호 변경, 타 기기 로그아웃, 이메일 수신 설정 API는 명세에 없어 구현된 것처럼 보이는 저장 버튼을 만들지 않았다. 비밀번호 변경은 연동 대기로 표시한다.
- 개발 DEMO는 `astra.demo.profiles.v1`에 사용자 ID별 이름·연락처만 저장한다. 별도 `astra.demo.member-status.v1`에 관리자 정지·해제 상태를 저장하고 DEMO 로그인/세션 조회에 반영한다. 프로필 PATCH로 권한·상태를 변경할 수 없다. DEMO 로그인 이메일을 계정 정보에 표시하며 다른 계정의 프로필은 변경하지 않는다. 실제 계정·토큰 저장소와 분리되고 production 번들에서 제외된다.
- 기업/기관 대시보드에 **의뢰 상태 도넛 차트**, **장비 가용 상태 막대 차트**를 추가했다. 이용자는 본인이 보낸 의뢰·검색 가능한 활성 장비, 제공자는 소속 조직이 받은 의뢰·보유 장비를 기준으로 본다. 10개 의뢰 상태를 빠짐없이 7개 표시 그룹으로 집계하고 미확인 가용 상태를 별도 표시한다. 가용 상태 분포는 실제 가동률을 의미하지 않는다. 기존 기관 14일 일정과 업무 이동은 유지했다.
- 관리자 대시보드는 6개 지표(전체 가입 회원/승인 대기/활성 장비/등록 기관·대학/진행 의뢰/확정 예약), 전체 의뢰 분포, 예약 상태 분포, 지역별 장비, 기관별 장비·확인 현황·진행 의뢰, 관리자 업무 4개와 최근 의뢰를 제공한다. 전체 가입 회원은 관리자 포함, 기관 수는 승인 전 기관·대학 포함, 진행 의뢰는 DRAFT/완료/반려/취소 제외, 확정 예약은 전체 기간의 `CONFIRMED` 예약 건수이다. 제안을 확정으로 집계하지 않는다.
- 기존 GET `/dashboard/summary`, GET `/dashboard/equipment-stats`, GET `/admin/users`, GET `/admin/organizations`, GET `/test-requests`, GET `/test-requests/{id}`만 사용한다. 기관 총계는 조직 목록 전체 페이지를 읽고, 예약 통계는 기존 `loadCalendar`로 의뢰 목록 전체 페이지와 상세의 reservations를 집계한다. 새 통계/전체 캘린더 API는 생성하지 않았다.
- 관리자에게 ‘시험 운영 관리’ 메뉴를 표시하고 의뢰 목록으로 연결한다. 회원 관리에는 역할/상태 필터, 가입일(미제공 시 미제공), 20명씩 페이지 이동을 추가했다. 기존 승인·거절·정지·기관 승인 API를 유지한다. DEMO 회원은 공개된 5개 활성 계정으로, 가입 승인 대기/거절 전이는 실제 서버 데이터가 필요한 별도 검증 항목이다.
- ‘보완 기한 경과 의뢰’는 `SUPPLEMENT_REQUESTED` 의뢰 중 `OPEN` 보완 요청의 dueDate가 한국 시간 해당일 마지막 시각을 지난 경우만 센다. 업무 지연 SLA를 임의로 가정하지 않는다. 기관 확인 게이지는 `verifiedCount/equipmentCount`로 그려 rate 필드의 %/소수 단위 모호함에 의존하지 않는다.
- `dataAvailable.requests=false`, API 오류/미제공 값은 연동 대기 또는 —로 표시한다. 데이터 0건은 실제 빈 상태를 표시한다. 월별 가입 추이와 장비 가동률을 임의 생성하지 않는다. DEMO 표시는 유지한다. 차트는 외부 라이브러리 없이 SVG/CSS로 구성하고, 숫자 범례와 한국어 상태를 함께 제공하며 모션 축소 환경을 따른다.

백엔드 후속 확인:

1. PATCH `/users/me`의 빈 연락처(빈 문자열) 허용 여부, 이름·전화번호 길이/형식 규칙, 기존 JWT 세션에서 GET `/users/me` 재조회 동작.
2. 장비 통계의 `verifiedCount`, `verificationRate` 제공 여부·단위, 기업 보유 장비도 institutions에 포함되는지 확인.
3. 현재 예약/기관 운영 집계는 의뢰 상세 N개 조회가 필요하다. 큰 데이터에서는 기간·기관별 예약 집계/조회, 월별 가입·의뢰 통계, 가동률 정의와 제공 API를 협의해야 한다. 현재 존재하지 않는 API를 호출하지 않는다.
4. 실제 인증/프로필 저장/승인/통계/예약 권한 통합 테스트는 **백엔드 미배포로 테스트 불가**. 실제 서버 배포 후 역할·조직별 접근 제한과 오류 응답을 검증한다.

검증 결과(2026-11-24): `check-account-operations.mjs`(프로필 검증/필드 허용 목록/계정 분리·정지 반영/집계/조직 페이지 조회), `check-functional-cleanup.mjs`(기존 인증·스타일 보존), `check-organization-flows.mjs`, `check-demo-payment.mjs`, `check-demo-boundary.mjs` 모두 통과. 브라우저에서 저장·재로딩·실패 후 재시도·기본 보기·테마·회원별 메뉴·관리자 6개 지표/3개 차트/4개 업무를 확인했다. 1920/1366/1280/390px 가로 넘침과 기존 기관 14일 일정·월간 캘린더·관리자 403 접근 거부 회귀 검증을 통과했다. `npm run lint`, `npm run build`(TypeScript 포함) 통과. 빌드에는 기존 대형 청크 안내가 있으며 기능 오류는 없다. 실제 통합 테스트는 위 백엔드 미배포 제한을 따른다.

## 회원별 화면과 거래 범위

| 구분 | 기본 메뉴·대시보드 |
|---|---|
| 기업·장비 이용 | 인사/6개 상태 요약, 작은 검색 배너, 최근 의뢰·다음 업무. 검색, 내 의뢰, 예약, AI, 알림 |
| 기관·장비 제공 | 접수 상태 요약, **14일 일정**, 접수 의뢰·보유 장비 상태. 장비 관리, 검토, 예약, 중복 조회, 알림 |
| 관리자 | 승인 대기·전체 장비, 운영 바로가기·데이터 상태. 회원/조직 승인, 장비 DB, 중복, 예약, 알림. 기업용 의뢰/AI 메뉴 제외 |

기업·기관·대학 모두 **장비 이용 / 장비 제공** 업무 전환 가능하다. 기본값만 가입 유형에 따라 다르며, 거래 가능 여부는 조직·소유권 기준이다. 기업→기업, 기업→기관, 기관→기관을 지원한다. 회사가 제공자가 되려면 제공 업무의 ‘새 장비 등록’을 통해 자기 조직의 DEMO 장비를 등록할 수 있다. 기존 실제 기관 장비의 소유자를 바꿔 기업 장비인 것처럼 만들지 않는다.

- 이용: `GET /dashboard/summary?view=REQUESTER`, `GET /test-requests?box=SENT`.
- 제공: `GET /dashboard/summary?view=PROVIDER`, `GET /test-requests?box=RECEIVED`.
- 의뢰자는 본인 건만, 제공자는 자기 조직 장비로 제출된 건만 확인한다. 다른 조직의 비공개 상세는 403.
- 자기 소속 장비에 의뢰 불가. 제출 전 DRAFT는 제공자에게 노출하지 않는다.
- 제공자 검토/이용료/예약 확정/결과 등록은 조직 소유권을 확인한다. 의뢰자가 자기 예약을 확정할 수 없다. 프론트 화면 제한은 실제 서버 권한 검사를 대신하지 않는다.

## 밀도와 편의성

- 대시보드: 첨부 레퍼런스에 맞춘 작은 인사 영역과 6열 상태 스트립. 미제공 집계는 0 대신 ‘—’. 검색 배너는 160px로 축소하고 위성 모션을 유지한다.
- 기관 대시보드: 14일 셀, 이전/다음 2주, 오늘, 전체 달력, 일정 클릭 상세. KST 기준. 기존 의뢰 목록·상세 API로 구성하며 전체 캘린더 API를 만들지 않는다.
- 전체 캘린더: 필터 UI/필터 상태 제거. 월 이동·오늘·새로고침·상태 범례·날짜 상세·기관 확인/중복 검사는 유지한다. 제공/이용의 데이터 범위를 분리한다.
- 검색: 기본 보기는 글 중심 목록이며, 이전에 저장한 카드/목록 선호는 유지한다. 목록에서 장식용 현미경/격자 패널을 제거하고 장비명·보유기관/시험유형/상태·정보 갱신/작업의 4열로 표시한다. 장비명을 누르면 상세를 열며 ID·지역·DEMO도 텍스트로 확인한다. 모바일에서는 정보와 버튼을 세로로 재배치한다. 동일 결과의 카드 전환은 유지하고 `astra.equipment-view.v1`에 표시 선호만 저장한다. 설정 화면의 미선택 기본값도 목록으로 맞췄다. 검색·비교·상세·의뢰 흐름과 선택 상태 유지. 2026-11-24 브라우저에서 목록 행 약 119px, 카드 전환 후 비교 선택 유지, 상세 열기, 비교/뒤로 가기, 검색 및 1920/1366/1280/1024/768/390/360px 화면을 검증했다.
- 보유 장비: 가용 상태·확인 상태·갱신 필요·시험유형·갱신일을 함께 표시. 가용 상태는 `PATCH /equipment/{id}`, 정보 확인은 `POST /equipment/{id}/confirm`. 실제 확인 여부는 사용자가 명시적으로 확인한다. 시험유형은 기존 수정 창에서 변경한다. 서버 갱신 사유가 없으면 미확인/90일 경과를 보조 표시한다.
- 의뢰 작성: ‘장비·상담 선택 → 내용 보완 → 최종 확인 → 제출·접수’ 4단계 표시. 제출 후에는 검토→일정 협의→예약→시험/성적서 단계 안내를 함께 표시한다. AI 자동 채우기·직접 수정·사용자 확인을 유지한다.

## 최종 서류 확인·DEMO 결제

사용자가 PG/API 미정이므로 DEMO 먼저 진행하라고 선택했다. **실제 결제 API/PG SDK를 발명하거나 외부 결제 요청을 보내지 않는다.** 카드번호·CVC·실제 카드정보는 받지 않는다.

1. 보유 조직은 검토 중/일정 협의 중 기존 `PUT /test-requests/{id}/estimated-fee`에 예상 이용료를 등록한다.
2. 의뢰자는 기관 검토를 통과한 뒤(SCHEDULING/CONFIRMED/COMPLETED) 의뢰·신청 조직·수행 조직·금액을 확인한다.
3. 체크박스로 최종 내용을 승인해야 ‘DEMO 결제 승인’ 가능. 실패 시연은 승인 내역을 만들지 않는다.
4. DEMO 상태는 `APPROVED_DEMO`, 번호는 `DEMO-PAY-*`. 같은 의뢰·견적·제출본은 중복 승인하지 않는다. 표시 금액과 최신 DEMO DB 금액을 비교하고 변경 시 409로 차단한다. 견적이나 제출본이 바뀌면 다시 확인한다.
5. 승인해도 예약 확정이나 시험 완료 상태를 바꾸지 않는다. 실제 영수증/세금계산서/정산 완료로 표시하지 않는다. 성공한 시연 내역은 DEMO DB의 `payments`에만 저장한다.

기관 결과 등록은 명세의 `PUT /test-requests/{id}/result`로 연결한다. 예약 확정 뒤 등록하며 DEMO도 결과 없이 완료 처리하지 못한다. 의뢰 상세에서 결과·성적서·예상 이용료·시연 결제를 함께 확인한다.

실제 결제에 추가로 필요한 합의: PG/가맹점·정산 주체, 최종 청구액 및 부가세, 주문 생성/서버 금액 검증/결제 승인, 멱등성·웹훅, 취소/환불, 영수증/세금계산서, 결제 권한·감사 기록. 백엔드 API 명세가 확정되면 `paymentService`의 DEMO 구현을 실제 서비스로 교체해야 한다. 현재 production은 ‘결제 API 연결 대기’다.

## 검증 및 제한

- `scripts/check-organization-flows.mjs`: 세 가지 거래 조합의 장비 등록→의뢰→검토→이용료→예약→결과→완료, 타 조직 403, 자기 장비 의뢰 금지, 이용자의 예약 확정 금지, 결과 전 완료 차단.
- `scripts/check-demo-payment.mjs`: 타인 결제 차단, 금액 불일치, 실패 무승인, 중복 승인 방지, 견적 변경 시 재확인, 의뢰 상태 불변.
- 브라우저: 잘못된 로그인·미인증 내부 URL·회원별 메뉴/업무 전환·관리자 403·14일 일정·카드/목록·필터 없는 전체 달력·모바일 폭 검증.
- 실제 계정 인증·Gemini·기관 접수·실제 카드 승인·정산·성적서 통합은 **백엔드 미배포 및 PG/API 미정으로 테스트 불가**다. DEMO 검증을 실제 서비스 연동 완료로 표시하지 않는다.
- 최종 결과: TypeScript·ESLint·Vite build(`--mode demo` 포함) 통과. production 자산에서 DEMO 비밀번호/세션/DB/결제 구현/seed가 제외됨을 검사했고 production 미인증 내부 URL과 `/preview/**`도 로그인으로 이동했다. 실제 JWT 서비스·세션/토큰·회원가입·공통 API 클라이언트 보존 검사를 통과했다.
- 브라우저에서 기업 제출→기관 검토/견적→기업 최종 확인→실패 시연→승인을 확인했다. 승인 내역은 1개이고 예약/의뢰 상태를 자동 변경하지 않았다. 보유 장비의 가용 상태·확인·시험유형 변경도 기존 API를 통해 갱신되는 것을 검증했다. 별도 테스트 데이터는 실행 후 원래 DEMO 저장소로 복원한다.
- 1920×1080·1366×768·1280×720에서 전체 달력 표시, 390px에서 가로 넘침 없음, 목록 행과 관리 행의 과도한 높이 없음 확인. 기존 Three.js 분리 청크의 500kB 경고는 남는다.
