# ASTRA 프런트엔드 남은 작업

- [주현욱](#주현욱) · 가입과 공통 권한부터 진행하고, 조직·장비 관리와 대시보드·알림을 담당한다.
- [이연지](#이연지) · 시험 의뢰서와 시험 완료 흐름부터 진행하고, 검토·예약과 AI 상담·매칭을 담당한다.

**P0** 가입·의뢰 제출·시험 완료에 필요한 작업 → **P1** 주요 화면 연동 → **P2** 부가 기능과 문서 보강

아래는 후속 작업 배분안이다. 현재 상태는 프런트엔드 코드와 문서를 대조한 기준이며, 실제 서버 응답은 연동 시 확인한다. [API 명세](api-spec.md) · [작업현황](dev-status.md)

## 두 사람이 함께 맞출 부분

- **소속과 권한** · 주현욱이 권한 기준을 백엔드와 확인해 공통 판별 로직을 만든다. 이연지는 이를 의뢰 목록·상세·예약에 적용한다. 그동안 이연지는 제출 필드와 결과 등록 작업을 먼저 진행할 수 있다.
- **기간 가용성** · 주현욱이 장비 가용성 조회 함수와 응답 타입을 만들고 장비 상세에 연결한다. 이연지는 같은 함수를 예약 입력과 캘린더에 사용한다.
- **결과 등록 알림** · 이연지가 결과·성적서 등록을 연결하고, 주현욱이 알림 목록과 헤더에서 수신·읽음 상태를 확인한다.

## 주현욱

### P0 · 가입과 공통 권한

- [ ] **기관·대학 담당자 가입** · 기존 소속 선택과 신규 소속 신청 모두에 8자리 국가연구자번호(`researcherNo`) 입력을 추가한다. 형식 오류를 해당 필드에 표시하고, 내 정보·관리자 회원 목록 응답 타입에도 반영한다.
  - 신규 조직 가입 예시에 빠진 필수 필드를 백엔드와 맞춘 뒤, 신청부터 관리자 승인까지 확인한다. [인증 명세 §1](api-spec.md#1-인증--사용자-be-a) · [가입 화면](../src/auth/SignupPage.tsx)
- [ ] **조직 기준 권한과 대시보드 전환** · 현재 역할별로 고정된 메뉴 권한을 소속 조직과 업무 범위에 맞춘다. 기관·대학 계정도 외부 장비 상담·매칭·의뢰에 접근하고, 장비를 보유한 기업 계정도 소속 장비 관리·접수 검토에 접근할 수 있어야 한다.
  - `view=REQUESTER/PROVIDER` 전환과 뷰별 응답 검증을 연결한다. 관리자 전용 뷰와 예외 권한은 따로 확인한다. [대시보드 명세 §10](api-spec.md#10-대시보드--알림-be-a--be-b--기능-14) · [대시보드 서비스](../src/services/dashboardService.ts)
  - §2-1의 기업 회원 403 안내와 같은 절의 장비 등록 표가 충돌한다. 백엔드와 실제 권한을 먼저 확인한 뒤, 소속 장비 판별 기준과 `box=SENT/RECEIVED` 적용 기준을 이연지와 공유한다. [권한 명세 §0-4](api-spec.md#0-4-권한-규칙) · [메뉴 권한](../src/auth/permissions.ts)

### P1 · 조직·장비 운영과 업무 현황

- [ ] **소속 장비 목록과 수정** · 공개 카탈로그를 필터링하는 관리 목록을 `GET /institutions/me/equipment`로 바꾸고 갱신 필요 여부와 이유를 표시한다. 등록의 `testTypes` 형식을 `[{ code }]`로 맞춘다. 사양 사전에서 키·단위·값 형식을 가져오고, 시험유형별 비용·기간·공인정보 수정까지 연결한다.
  - 가용 상태 근거·대기 일수·운용 방식 입력을 추가한다. 일반 정보 저장에서는 가용 상태를 명시적으로 확인했을 때만 `usage.availability`를 보낸다. [장비 관리 명세 §2-1](api-spec.md#2-1-기관-장비-관리--장비-정보는-기관이-직접-등록갱신) · [장비 수정 화면](../src/components/workflow/EquipmentEditDialog.tsx)
- [ ] **기관 안내·보안·정비·변경 이력** · 현재 장비 목록으로 구성하는 기관 안내에 기관 상세와 보안 정보 조회를 연결한다. 소유 조직과 관리자에게 명세상 허용된 보안 수정·정비 구간 등록 및 삭제·장비 변경 이력 조회를 연결한다. [장비·기관 명세 §2](api-spec.md#2-장비--검색--시험정보-be-a--기능-123412) · [기관 목록 화면](../src/components/dashboard/InstitutionNetwork.tsx)
- [ ] **기간 가용성 조회** · `GET /equipment/{id}/availability`를 연결한다. 장비 상세에서 기간을 선택하면 정비·이용 불가·확인 필요 상태를 표시한다. 조회 함수와 응답 타입을 이연지에게 공유한다. [사양·가용성 명세 §2-2](api-spec.md#2-2-사양-사전가용성현업-정보-v6) · [장비 상세](../src/components/EquipmentDetailDialog.tsx)
- [ ] **관리자 조직 관리** · 기존 회원 승인·정지와 조직 승인 화면에 기관·대학 등록, 조직 정보 수정, 장비 이관을 추가한다. 회원·조직 목록의 명세 필터와 페이지 이동도 연결한다. 장비 일괄 가져오기는 명세에 미구현으로 표시되어 있으므로 서버 제공 이후에 연동한다. [관리자 명세 §12](api-spec.md#12-플랫폼-관리자-be-a--마스터) · [관리자 화면](../src/components/AdminManagement.tsx)
- [ ] **대시보드 요약과 읽지 않은 알림** · 장비 통계 API를 연결하고, 최근 상담·예정 예약·갱신 필요 장비·기관 검증 현황을 해당 뷰에 표시한다. `dataAvailable.chats`가 거짓이면 최근 상담을 준비 중으로 표시한다.
  - 헤더에 `GET /notifications/unread-count`를 연결하고 목록에 `unreadOnly=true` 필터를 추가한다. 읽음 처리 후 헤더 숫자와 결과 등록 알림이 반영되는지 확인한다. [대시보드 화면](../src/components/Home.tsx) · [알림 서비스](../src/services/notificationService.ts)

## 이연지

### P0 · 의뢰서 제출과 시험 완료

- [ ] **의뢰서 제출 필수 항목** · 초안과 AI 생성 의뢰서에 실사용자·회계 담당자의 이름과 연락처(전화 또는 이메일), 희망 시작·종료일을 입력할 수 있게 한다. 신청자 기본값과 기존 초안의 누락값을 처리하고, 서버가 반환한 `details.missingItems`를 각 입력란에 표시한다. [시험 의뢰 명세 §5](api-spec.md#5-시험-의뢰-be-b-ai-초안은-be-c--기능-89) · [의뢰서](../src/components/Reservation.tsx)
- [ ] **보낸 의뢰·받은 의뢰와 상세 권한** · 목록에 `box=SENT/RECEIVED`를 명시하고, 주현욱이 정리한 공통 권한 기준을 상세·검토·예약 버튼에 적용한다. 기관·대학이 보낸 의뢰와 장비 보유 기업이 받은 의뢰를 각각 확인한다. 자기 조직 장비는 직접 의뢰와 AI 초안 생성에서 제한한다. [의뢰 목록](../src/components/ReservationCheck.tsx) · [상태 전이표 §11](api-spec.md#11-의뢰-상태-전이표-be-b-구현--fe-버튼-노출-기준)
- [ ] **예상 이용료·결과 등록·시험 완료** · `PUT /test-requests/{id}/estimated-fee`와 `PUT /test-requests/{id}/result`를 연결한다. 당사자 양쪽의 상세에 이용료와 결과를 표시하고, 소유 조직이 허용된 상태에서 입력·수정할 수 있게 한다. 결과가 등록된 확정 의뢰에서 완료를 허용한다. [검토 명세 §6](api-spec.md#6-기관-검토--보완-be-b--기능-10) · [의뢰 상세](../src/components/workflow/RequestDetailDialog.tsx)

### P1 · 검토·예약과 AI 연동

- [ ] **추가 정보 요청과 제출본 비교** · 기존 보완 요청에 `ADDITIONAL_INFO` 유형과 책임자명·성적서 종류·시료 처리·청구 방법 응답을 연결한다. 열린 요청 외에 보완 목록을 볼 수 있게 하고, `GET /test-requests/{id}/revisions/{no}?diffWith=…`로 제출본 간 변경을 보여준다.
  - 의뢰서의 선택 항목인 공인성적서·운용 지원·보안 협의는 `serviceRequirements`에 미확인 여부까지 반영한다. [의뢰 서비스](../src/services/requestService.ts) · [보완 화면](../src/components/workflow/RequestDetailDialog.tsx)
- [ ] **일반 첨부와 성적서 파일** · `GENERAL`과 `RESULT_REPORT`의 등록·목록·인증된 다운로드·삭제를 연결한다. 파일당 20MB와 허용 확장자를 검증하고, 상태별 업로드 권한과 업로더·관리자 삭제 권한을 적용한다. 성적서 첨부와 결과 등록을 상세에서 각각 확인할 수 있게 한다. [첨부 명세 §5](api-spec.md#5-시험-의뢰-be-b-ai-초안은-be-c--기능-89) · [의뢰 상세](../src/components/workflow/RequestDetailDialog.tsx)
- [ ] **예약 조회와 기간 가용성 표시** · 장비 확정 예약 조회에 기간을 넘긴다. `GET /test-requests/{id}/reservations`로 의뢰별 예약 목록을 읽고 `proposedBySide`에 따라 제안 주체를 표시한다. 공통 가용성 조회를 예약 입력과 캘린더에 연결해 정비·이용 불가·확인 필요를 표시한다. [예약 명세 §7](api-spec.md#7-예약-be-b--기능-11) · [예약 조작](../src/components/workflow/ReservationControls.tsx)
- [ ] **이전 상담·조건 확정·매칭 이력** · 상담 목록에서 기존 세션을 다시 열고, 조건 확정과 매칭 결과 단건 조회를 화면에 연결한다. 조건별 매칭 이력을 조회하고, 매칭 실행에서 지역을 선택할 수 있게 한다. 추천 카드에 가용 상태·확인 필요 여부·공동활용 범위를 표시한다. [상담 명세 §3](api-spec.md#3-ai-상담--조건-분석-be-c--기능-56) · [매칭 명세 §4](api-spec.md#4-ai-매칭--비교-be-c--기능-7) · [매칭 화면](../src/components/Matching.tsx)
- [ ] **상담 이어서 자동 추진** · 직접 입력 흐름에 기존 상담 선택과 `chatSessionId` 전달을 추가한다. `PENDING` 상태에서 `RUNNING`으로 바뀔 때까지 진행 조회가 이어지는지 확인한다. [자동 추진 명세 §8](api-spec.md#8-ai-자동-추진-be-c--기능-13) · [자동 추진 화면](../src/components/Automation.tsx)

### P2 · 부가 기능

## 서버 연동 후 함께 확인할 흐름

1. 기관·대학 가입 신청 → 관리자 승인 → 외부 장비 의뢰 → 장비 보유 조직의 접수 확인
2. 의뢰 제출 → 추가 정보 요청·재제출 → 예상 이용료 입력 → 일정 확정 → 결과·성적서 등록 → 시험 완료 및 알림 확인
3. 자기 조직 장비 의뢰 제한, 정비와 확정 예약의 중복, 오래된 `version`으로 수정할 때의 오류 표시
