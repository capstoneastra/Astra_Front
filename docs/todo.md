# ASTRA 프런트엔드 남은 작업

현재 작업 트리의 API 명세 초안과 README·기술 스택·작업현황을 읽고, 화면 진입점과 서비스 호출을 대조했다. **미연동**은 화면이나 서비스에서 해당 계약을 사용하는 경로가 확인되지 않은 상태다. **부분 연동**은 기본 경로는 있으나 명세의 필드·옵션·권한이 빠졌거나 응답을 다른 경로로 받고 있는 상태다. 실제 서버 응답과 배포 상태는 미확인이다. [API 명세](api-spec.md) · [작업현황](dev-status.md) · [README](../README.md)

## 3. 주현욱·이연지 작업 배분안

작업현황에는 주현욱의 인증·회원가입·역할별 미리보기 작업이 기록되어 있고 이연지 항목은 비어 있다. 아래는 앞으로의 작업 배분 제안이다. [작업현황](dev-status.md)

| 순서 | 주현욱 | 이연지 |
| --- | --- | --- |
| 1 · P0 병렬 착수 | 인증·권한 공통 작업을 맡는다. `researcherNo`, 권한 판단 기준, `view`·`box` 쿼리와 관리자 예외를 백엔드와 확인한다. 기업·기관·대학·관리자 메뉴와 대시보드의 뷰 전환을 연결한다. | 의뢰 작성부터 시험 완료까지 맡는다. 실사용자·회계 담당자·희망 기간과 필드 오류를 반영하고, 예상 이용료·결과 등록과 완료 조건을 연결한다. 기존·AI 생성 초안을 처리하고, 보낸함·받은함 및 상세 액션에 합의한 소유권 기준을 적용한다. |
| 2 · P1 주요 화면 연동 | 조직·장비 운영을 맡는다. 소속 장비 목록·사양 사전·시험유형·정비·장비 이력·기관 보안을 연결하고, 관리자 조직 관리·장비 이관과 대시보드 집계·알림을 완성한다. 정비 구간을 관리하는 화면과 예약 화면이 사용할 기간 가용성 조회 계약을 공유한다. | 의뢰 상세·예약·AI 흐름을 이어서 맡는다. 추가 정보 요청과 재제출, 제출본 비교, 첨부·성적서, 기간 가용성 표시를 붙인다. 상담 목록에서 기존 세션을 열고 조건 확정·매칭 이력 및 상담 기반 자동 추진까지 이어지게 한다. |
| 3 · P2 및 문서 보강 | 내 정보 수정, 고급 장비 검색·비교를 연결하고 개발용 미리보기와 작업공간 설정을 문서화한다. | 상담 SSE와 시뮬레이션 이력 필터를 연결한다. 캘린더의 범위·데이터 원천과 3D 뷰어·GLB·내보내기 동작을 문서화한다. 자동 추진 SSE는 기능 필요성과 서버 지원이 확인되면 진행한다. |

- 주현욱이 공통 역할·조직 식별과 API 응답 계약을 정리하면, 이연지는 해당 계약을 의뢰·예약 상세에 적용한다. 인증·장비 타입은 주현욱, 의뢰·예약·매칭 타입은 이연지가 담당한다. 같은 파일을 병렬 수정할 때는 계약 변경을 먼저 병합한다.
- 첫 통합에서는 기관·대학 가입 신청부터 관리자 승인까지 확인한다. 이어서 기업의 소속 장비 관리, 기관·대학의 외부 장비 의뢰, 자기 조직 장비 의뢰 제한, 양쪽의 의뢰 목록 범위와 관리자 예외를 확인한다.
- 업무 통합에서는 시험 의뢰 저장·제출 → 추가 정보 요청·재제출 → 예상 이용료 → 일정 제안·확정 → 결과·성적서 → 완료를 실제 API에서 확인한다. 정비와 확정 예약이 겹치는 경우, 오래된 `version`으로 변경하는 경우, 읽지 않은 알림 수가 갱신되는 경우도 확인한다.
