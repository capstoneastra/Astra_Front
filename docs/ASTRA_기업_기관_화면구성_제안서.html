기업·기관별 페이지 구성 및 대시보드 제안서

기업은 “시험을 찾고 진행 상황을 확인하는 화면”
기관은 “접수된 의뢰를 처리하고 장비·일정을 관리하는 화면”

같은 기능을 모두 나열하기보다, 각 회원이 지금 해야 할 일을 첫 화면에서 바로 찾도록 구성합니다.

장비 탐색 → 조건 정리 → 장비 비교 → 의뢰 제출 → 보완 답변 → 일정 확인

들어온 시험 의뢰를 빠르게 처리

접수 확인 → 조건 검토 → 보완 요청 → 기술 검토 통과 → 일정 협의·확정

01 · 기업 대시보드

“시험 찾기”와 “내가 처리할 일”을
가장 먼저 보여주는 것이 좋습니다.

기업 담당자가 접속하자마자 장비를 찾거나, 보완 요청과 다가오는 시험 일정을 확인할 수 있도록 합니다.

준비물 또는 안내사항예약 상세보기
최근 시험 의뢰의뢰명 · 기관 · 진행 상태 · 갱신일의뢰 상세보기
AI 상담 진입우측 공통 AI 버튼으로 상담·자동 추진 연결시험 상담 / 자동 추진

배치 개념도입니다. 숫자·장비·의뢰를 임의 데이터로 채우지 않고 영역의 역할만 표시했습니다.

영역보여줄 정보필요한 이유·연결
큰 검색 영역장비명·시험항목·자연어 입력과 검색 버튼기업의 첫 행동인 장비 탐색을 바로 시작
보완 요청의뢰명, 기관 요청 내용, 미제출 항목, 기한이 있으면 기한사용자 행동이 필요한 의뢰를 우선 처리
다가오는 시험시작·종료 시간, 장비, 기관, 예약 확정 여부방문·시료 준비에 필요한 정보를 확인
최근 의뢰의뢰번호·제목·최신 상태·기관·갱신 시점다시 검색하지 않고 진행 중 업무로 복귀
우선순위 제안 · 보완 요청 → 확인할 일정 제안 → 확정 시험 순서로 강조합니다. 기관의 전체 접수 현황이나 다른 기업의 의뢰는 표시하지 않습니다. 집계 기준은 서버 제공 범위에 맞춰 확정합니다.

02 · 기업에 필요한 페이지

탐색에서 의뢰·보완·예약까지
하나의 흐름으로 연결합니다.

자주 쓰는 업무는 기본 메뉴에 두고, 비교·시험 정보·시뮬레이션은 장비 검색의 후속 단계로 연결합니다.

페이지무엇을 보여줄지어떻게 이용하게 할지
시험장비 검색
기본 메뉴		큰 검색창, 지역·기관·시험유형 필터, 장비 카드, 결과 건수검색 기준이 달라도 결과는 같은 카드 목록에 표시. 상세·비교 후 돌아오면 검색어·필터·페이지 유지.
장비 상세·비교
검색 내 연결		사양, 가능 시험, 기관, 비용·기간, 이용조건, 갱신일, 장비별 차이상세 모달 → 2~5대 비교 → 시험 의뢰. 확인되지 않은 사양·비용은 ‘확인 필요’로 표시.
AI 상담·자동 추진
공통 AI 버튼		대화, 추출한 시험조건, 미확인 항목, 자동 추진 단계버튼을 열면 상담/자동 추진을 별도 탭으로 진행. 분석·매칭을 거쳐 의뢰서 작성까지 연결하고 제출 전 직접 확인.
시험 의뢰서
선택 장비에서 진입		선택 장비, 기업·담당자, 시료, 시험 목적·조건, 희망 기간, 필수 정보상담 조건을 반영하고 사용자가 수정·검토 후 제출. 수동 초안 저장 버튼은 두지 않으며 기관 검토 후 예약 협의.
내 시험 의뢰
기본 메뉴		본인 의뢰 목록, 진행 상태, 기관 요청, 제출 정보·이력, 예약상태별 필터 → 상세보기 → 보완 요청에 답변·자료 제출 → 재제출. 기관의 검토 버튼은 표시하지 않음.
내 예약 캘린더
기본 메뉴		본인 시험 일정, 제안/대안/확정/취소 상태, 장비·수행기관날짜 선택 → 예약 상세 → 의뢰 상세. 일정 협의 가능한 의뢰에서만 제안하며 기관 확정 전까지 ‘미확정’ 표시.
시험 정보·시뮬레이션
보조 페이지		시험별 필요 조건·수행 정보, 가상 모델 입력과 결과 그래프검색 장비의 맥락을 유지. 결과가 있을 때만 그래프와 Excel/CSV/PDF 제공. 가상 결과는 DEMO로 구분.
업무 알림
기본 메뉴		보완 요청, 검토 결과, 일정 제안·확정 등 본인 업무 알림알림 클릭 시 관련 의뢰·예약으로 바로 이동. 처리할 일과 일반 안내를 구분.
기업 화면에서 기본 제외 · 타 기업 의뢰, 기관의 승인·반려 화면, 전체 회원 승인, 전체 장비 운영 기능. 기업이 직접 보유 장비를 운영하는 경우는 별도 보유자 작업공간으로 검토합니다.

03 · 기관 대시보드

“들어온 의뢰”와 “장비 일정”을
가장 먼저 보여주는 것이 좋습니다.

기관 담당자에게는 큰 장비 검색 배너보다 신규 접수·보완 회신·예약 검토가 더 중요합니다. 업무 대기 목록을 화면 중심에 배치합니다.

기관 업무 대시보드보유 장비 관리 / 접수 의뢰 검토
보유 장비소속 장비 현황
검토 대기신규·재제출
보완 회신다시 검토할 일
일정 협의확정 전 예약
신규·재제출 의뢰 대기 목록의뢰번호 · 신청 기업 · 시험유형
선택 장비 · 접수 시점 · 상태검토 시작 / 의뢰 상세보기
오늘·다가오는 장비 일정장비별 예약 시간 · 확정 상태
기관 일정 캘린더로 연결장비 일정 확인
보완 회신·일정 검토기업의 추가 제출 내용
기업/기관이 제안한 일정 구분보완 내용 확인 / 예약 검토
장비 정보 관리갱신일 · 누락된 사양/이용조건
등록 정보의 확인 상태장비 수정 / 현재 정보 확인

기업용 검색·상담 히어로를 그대로 복제하지 않고 접수 업무와 장비 운영을 중심에 둔 배치안입니다.

영역보여줄 정보필요한 이유·연결
의뢰 대기 목록신청 기업, 시험, 장비, 접수일, 신규/재제출, 담당자 정보가 있으면 담당자어떤 의뢰부터 검토할지 빠르게 판단
보완 회신요청한 자료, 기업 답변, 변경·재제출 시점이미 답변이 온 의뢰를 놓치지 않고 재검토
일정 검토제안/대안 일정, 장비의 확정 점유, 예약 상태확정 일정과 구분하여 충돌을 확인
장비 관리소속 장비, 정보 갱신일, 사양·조건 누락, 정보 확인 상태검색·매칭에 쓰일 장비 정보의 정확도 관리
우선순위 제안 · 신규·재제출 검토와 보완 회신을 상단에, 예약 검토와 장비 갱신을 다음에 둡니다. 갱신 필요 기준이나 업무 기한은 기관과 합의한 뒤 적용하며 임의의 ‘지연’ 기준을 만들지 않습니다.

04 · 기관에 필요한 페이지

장비 관리와 의뢰 검토를
업무 단위로 분리합니다.

소속 기관 장비로 들어온 의뢰만 처리하고, 검토·보완·예약 확정을 서로 다른 단계로 보여주는 구성을 권장합니다.

페이지무엇을 보여줄지어떻게 이용하게 할지
보유 장비 관리
기본 메뉴		소속 장비 목록, 장비명·규격·시험유형, 이용조건, 갱신일, 정보 확인 상태장비 선택 → 상세 수정 → 서버 저장·재조회. 등록·수정·정보 확인 버튼은 소속 장비에 한해 제공.
접수 의뢰 목록
기본 메뉴		의뢰번호, 기업, 시험유형, 장비, 접수 시점, 상태, 보완 회신 여부신규/검토 중/보완 대기/재제출/일정 협의로 필터. 한 목록 안에서 상태를 구분하고 상세로 이동.
의뢰 검토 상세
목록에서 진입		시료·부품 정보, 시험 목적·조건·규격, 희망 기간, 제출 자료, 변경·처리 이력기업 제출 내용과 기관의 검토 영역을 구분. 검토 시작 → 자료 확인 → 보완 요청 또는 기술 검토 통과·반려.
보완 요청·회신
의뢰 상세 내		누락 항목, 요청 사유·기한, 기업 답변, 추가 첨부, 재제출 내용요청 항목을 명확하게 작성하고 기업 회신 확인 후 재검토. 답변 대기 중인 동일 요청은 중복 생성 방지.
기관 예약 캘린더
기본 메뉴		소속 장비별 예약, 제안·대안·확정·취소, 의뢰번호, 신청 기업장비/상태 필터 → 날짜 상세 → 점유 확인 → 대안 제안 또는 확정. 확정은 서버 응답 이후 표시.
시험 진행·결과
의뢰 상세 내		확정 일정, 진행 상태, 결과 요약·성적서 등 등록 정보예약 확정 뒤 명세가 허용하는 결과 등록·완료 처리. 예약 확정 자체를 시험 완료로 표현하지 않음.
중복 장비 조회
장비 관리 보조		지역·시험유형별 유사 장비, 보유 조직, 사양·정보 갱신일신규 도입 검토 시 사용. 유사 장비 목록을 보여주되 중복 구축 가능/불가를 자동 확정하지 않음.
업무 알림
기본 메뉴		신규 의뢰, 기업 보완 회신, 일정 변경·취소 등 기관 업무 알림의뢰 검토·예약 상세로 바로 연결. 기업용 알림과 같은 분류·문구를 그대로 재사용하지 않음.
기관 화면에서 기본 제외 · 큰 신규 시험 검색 배너, 기업용 의뢰서 작성·AI 자동 추진 메뉴, 다른 기관의 비공개 접수 내역, 회원 승인 기능. 외부 장비를 이용하는 기관의 의뢰자 업무는 별도 전환으로 검토합니다.

05 · 기업과 기관의 연결 흐름

같은 의뢰를 보더라도
각자 해야 할 행동은 다릅니다.

의뢰 상세의 공통 정보는 재사용하고, 현재 단계와 사용자의 업무에 따라 주요 버튼·안내·확인 항목을 바꿉니다.

장비 탐색→의뢰 제출→기관 검토→보완·재검토→일정 협의·확정

“어디까지 진행됐는가?”
“내가 더 제출할 것이 있는가?”
“언제 시험을 진행하는가?”

기관 검토 상세의 중심

“이 장비에서 가능한 조건인가?”
“어떤 정보가 부족한가?”
“어느 시간에 확정할 수 있는가?”

상태를 섞지 않습니다. ‘기술 검토 통과’는 예약 확정이 아니고, ‘일정 제안’도 확정이 아닙니다. ‘예약 확정’ 역시 시험 완료와 구분합니다. 실제 기관의 승인·예약 절차는 담당자와 확인 후 확정합니다.

06 · 관리자 전용 화면 제안

회원 승인과 데이터 품질을
운영 화면의 중심에 둡니다.

기업의 신규 의뢰 화면을 복제하지 않고, 관리자가 처리해야 할 승인·검증·운영 업무부터 보여줍니다.

플랫폼 운영 대시보드승인 관리 / 데이터 검토
회원 승인 대기가입 신청 검토
조직 검증 대기기업·기관 확인
장비 정보 갱신미확인·누락 정보
예약 현황전체 기관 모니터링
우선 처리할 승인신청자·조직·신청일·승인 상태회원/조직 검토로 이동
장비 데이터 검토정보 누락·갱신일·유사 장비 후보장비 상세 / 중복 검토

집계 API가 제공하지 않는 수치는 임의로 생성하거나 0으로 표시하지 않습니다.

기본 메뉴보여줄 정보주요 행동·제한
운영 대시보드승인 대기·조직 확인·정보 갱신·예약 현황우선 처리 항목에서 관련 목록·상세로 이동. 미제공 지표는 준비 중 표시.
회원·조직 관리회원/조직 유형, 소속, 신청 정보, 승인 상태검토 → 승인·거절 또는 정지. 사유·처리 이력과 확인 절차 유지.
장비 데이터 관리전체 장비, 보유 조직, 사양 출처, 갱신일필터 → 상세 검증·정정. 미확인 정보는 검증 완료로 표시하지 않음.
중복·갱신 검토동일·유사 장비 후보, 규격 차이, 정보 누락비교 → 기관 확인. 유사 후보만으로 실제 중복을 자동 확정하지 않음.
예약 모니터링기관·장비·예약 상태별 전체 일정필터 → 일정/의뢰 상세. 운영상 대신 처리 시 서버 권한과 이력 필요.
운영 알림승인·데이터·운영 요청 중 API 제공 항목필요한 업무로 직접 연결. 미구현 신고·오류 수집 기능을 완료로 표시하지 않음.
관리자 기본 화면에서 제외 · 기업용 큰 검색 히어로, AI 상담·자동 추진, 신규 의뢰, 개인 시뮬레이션. 필요한 운영 조회는 장비·의뢰 상세에서 보조 진입합니다. 이는 메뉴 구성 제안이며 서버의 관리자 마스터 권한을 축소하는 규칙이 아닙니다.

기업과 기관의 차이는 색상을 바꾸는 데서 끝나지 않고, 첫 화면·메뉴·주요 정보·행동 버튼에 반영하는 것이 좋습니다.

항목제안·확인할 내용
대시보드 우선순위기업은 보완 요청·다가오는 시험, 기관은 신규/재제출 의뢰·예약 검토를 우선 표시하는 안으로 합의.
기관 운영 절차검토 담당자 지정, 자료 요청 항목, 검토 통과 기준, 예약 확정 권한과 실제 업무 절차 확인.
지표의 기준‘진행 중’, ‘검토 대기’, ‘보완 회신’, ‘갱신 필요’의 범위와 집계 방식 확정. 서버에 없는 지표는 우선 숨기거나 준비 중 표시.
겸업 회원기업도 장비를 보유하거나 기관도 외부 장비를 의뢰할 수 있으므로, 기본 메뉴와 보조 작업공간 전환 범위를 협의.

권장 적용 순서

01

기업·기관의 기본 메뉴와 대시보드를 먼저 구분
공통 컴포넌트를 사용하되 첫 화면의 내용·버튼·우선순위를 분리합니다.

02

의뢰 목록·상세·보완·캘린더를 양측 흐름으로 연결
기업은 본인 제출 건, 기관은 소속 장비 접수 건을 기준으로 보여줍니다.

03

AI·비교·시뮬레이션을 필요한 위치에 연결
기업의 탐색을 지원하는 보조 기능으로 묶고 기관의 주요 접수 업무를 가리지 않게 합니다.

적용 전제 · 최신 저장소 API 명세는 역할명뿐 아니라 본인 의뢰·소속 조직·장비 소유권으로 업무 범위를 판단합니다. 이 제안의 기본 메뉴가 서버 권한을 대체하지 않습니다. 관리자에게는 승인·데이터 운영 중심의 별도 화면을 두는 것을 권장합니다.
